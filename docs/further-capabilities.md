# 后续可增加的功能与自由度

当前二十项路线有基础代码，但部分细节或验收未完成，先看[逐项复核与缺口](twenty-item-audit.md)；下面是继续扩展的方向，不表示已经接入，也不是一次添加越多越好。每项都应先定义真实回执、范围、失败与撤销，再决定是否值得增加常驻资源。

| 方向 | 可增加的能力 | 前提与边界 |
|---|---|---|
| 更好的语义记忆 | 词法/向量混合召回、多事件关联、置信度与冲突可视化 | 用真实召回评估证明收益；外部嵌入目的地和成本单独授权；保持私聊/群隔离 |
| 长期项目协作 | 里程碑、任务依赖、跨日检查点、版本化资料、归档/回收站 | 权限留在人类配置；生成笔记可撤销，不静默删用户原件 |
| 结构化资料库 | 独立书影音清单、标签、索引、引用图与更细的私密分类 | 真实阅读/采样与想读/想看的计划分开；资料过期与更新可解释 |
| 语言与群聊节奏 | 更细的笑点承接、多群不同表达、拥挤群中的轮次选择 | 关注误插话率与打断次数；不把群体意见当每个成员偏好 |
| 情感长期评估 | 数周连贯性、个体反馈、盲测、不同状态对照 | 不只挑成功例子；不以回复频率、依赖或亲密词数当质量指标 |
| 语音 | ASR、可选TTS、语音语气和字幕理解 | 先确认模型/算力与数据目的地；语音不是默认开放的新隐私收集 |
| 更深的视频理解 | 合法字幕、分段时间轴、跨视频笔记、可核对的音画理解 | 无字幕/音频时继续如实说明；重计算放有能力设备；公开互动仍沿用禁用 |
| 文档能力 | 更完整扫描PDF、多语言OCR、复杂表格和公式、可编辑Office产出 | 按格式建立真实样例和质量界限；宏与未知可执行内容继续排除 |
| 日历/邮件 | 账号内查询、建日程、按授权发信、提醒回执 | 需要独立账号授权、最小范围和明确外发边界；现有提醒不等于已接日历 |
| 桌面/移动设备 | Windows/Android受控MCP、观察界面后完成多步任务 | 需要相应真实设备与服务；iPhone另行核验；不推断已登录所有App |
| 发布与协作 | 形成草稿、资料卡、版本提交、审核后发布 | 账号/项目范围明确；陌生联系人、公开发布与付款不由网页授予权限 |
| 维护诊断 | 更细的模块语义探针、故障分类、依赖兼容性检查、证据化修复建议 | 既有确定性修复不依赖模型；新逻辑修复在无生产数据环境验证 |
| 受控代码改进 | 对列举低风险组件提出补丁、运行完整隔离回归与权限不变量检查 | 测试通过不等于证明任意代码安全；权限、密钥和边界代码另有发布门槛 |
| 发布工程 | 全新机器的一键安装、镜像离线备份、架构矩阵、签名与物料清单 | 固定已验证版本；更新先在隔离环境，不自动追latest |
| 十年运维 | 离机/异地备份、长期保留策略、UPS、硬件看门狗、存储寿命和恢复演练 | 需要实际硬件/备份目的地；不能靠聊天模型修复停电或坏盘 |
| 低资源优化 | 自适应模型额度、内容变更检测、批量检索、缓存命中与资源趋势 | 不把不同人的私人资料共享缓存；按体验、成功率和花费一起比较 |
| 控制面板 | 当前目标、来源、执行回执、失败与剩余额度的可视面板 | 展示简短决策与真实动作；不展示内部推理或他人私聊 |
| 更细自由等级 | 按工具/对象/时段/预算的独立许可、临时租约、到期撤销 | 模型可在许可中选择，不能自己扩许可；保留全局暂停与审计 |

最大可持续自由度取决于反馈、资源与可恢复性，不能只靠解除限制。优先选择能带来可测体验提升、失败后可解释和可撤销的扩展。
