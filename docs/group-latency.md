# 群内主动回复延迟修复

2026-10-25。此更改针对收到群消息后，由原生概率线路或 P1 兴趣线路触发的接话。后台自主活动按计划等待的时间不是一次模型回复的耗时，不能把离上一条群消息的间隔当作模型延迟。

## 发现与处理

| 环节 | 原有问题 | 处理 |
|---|---|---|
| 兴趣判定 | 与后台 max 研究共用信号量，取得信号量前的等待不在模型超时内 | 单独前台信号量；忙时跳过过期机会；整个操作限 4.5 秒，SDK 超时 4 秒、重试 0 |
| 判定输入 | 简单“是否加入”也带完整人格、自治说明和较长上下文 | 小型结构化判定，只读当前话题、至多 4 条近期资料和匹配兴趣；最多 160 输出 token；保持保守否决及授权、额度复核 |
| 正式群内接话 | 普通自动接话常被送到 max 思考 | 对7至300字且没有当前或近期复杂情境信号的两路自动接话，使用同一 DeepSeek 模型的快速参数别名：关闭 thinking，最多 2048 输出 token |
| 情感评估 | 分类器信号量等待、提供商查找不受原来的网络调用超时约束 | 忙时立即使用已有保守评估；整个评估限 5 秒，仍注入本群和当前成员的独立情感状态 |
| 排查依据 | 缺少一次回复各阶段的计时 | 只存无正文、无账号和群号的阶段耗时；不写内部思考或模型原文 |

复杂话题、明确 @、私聊和后台深度活动继续沿用原有选择策略；仍可使用获准的深入权衡工具。自动快速路径的信号是长度与显式关键词启发式，不能保证识别所有隐含复杂情绪。若快速配置缺失、格式不符或实际提供商不在已批准的 DeepSeek 地址，回退原有选择流程，不修改全局或会话默认模型。

发送前随机 2–5 秒间隔、统一发送锁、群内独立上下文、图片来源校验、两路独立开关、额度、免打扰、迟到权限撤销及真实 QQ 回执保护继续保留。省去的是判定和排队的多余等待；没有承诺所有回复都能在固定秒数内到达。

## 复现快速参数

`scripts/configure_quick_provider.py` 默认只检查，不修改。指定 AstrBot 数据目录；实际应用需要添加 `--apply`。它从当前默认模型复制一个本地参数别名 `deepseek-quick/deepseek-flash`，要求现有启用模型为 `deepseek-flash`，来源为 HTTPS `api.deepseek.com`。复制原有模态与模型上下文配置，继续引用原账号；只覆盖别名 ID 与 `custom_extra_body`，不复制密钥到输出、不创建外部账号、不改变默认模型或日调用额度。

应用前在项目 `backups/quick-provider-时间/` 创建权限 0600 的配置备份，随后原子替换配置；发现已存在但内容不同的别名或并发配置变化会拒绝写入。备份含登录配置，应只留在服务器。完成测试后按正常受控部署流程重启 AstrBot，让新别名进入运行时提供商管理器；插件启动完成后的健康探针确认实际实例，而不把配置行等同于成功加载。

## 观测

`plugin_data/affect/group_latency_last.json` 仅保留最近一条获得真实发送回执的群回复首段。包含选中线路、思考档、总毫秒数及路由、准备、生成与工具、后处理、发送队列、必要发送延迟、传输阶段耗时。没有相应边界时为 null。`/思考状态` 展示当前范围快速和 max 的选择计数，选择次数不等于 API 成功次数。

起点是插件群路由入口，不包含消息在 QQ 或框架之前的等待；传输阶段还包含本地回执记账，并不是 QQ 网络的单独测量。准备和生成边界按插件钩子记录，并非底层 HTTP 分布式追踪。文件不包含群号、用户号、原始内容或内部思考；不对模型开放任意日志读取。

## 测试与实际限制

以下数字为旧版历史证据；v0.21 的五轮和新增边界见[本轮核对](design-verification-20261029.md)。

旧版完整离线测试 341 项；中性核心测试 171 项。实际安装的 AstrBot SDK 隔离验证：后台信号量占用时前台判定仍完成；前台忙时不排队或消耗 API 额度；3 秒整体超时、撤销、取消与信号量释放；情感分类忙时立即回退且保留情感提示；提供商查找也受整体 5 秒约束。真实路由验证普通自动接话选择快速别名、复杂点名进入 max，普通点名沿用默认配置、计时只在真实格式的假回执后落盘。独立开关、延迟撤销、群图片与范围隔离回归通过。测试均使用临时数据库与假 QQ 传输，未向真实群发送测试消息。

对同一现有账号、同一模型、两条合成短句交替比较 max 与 quick，共 4 次真实 API 请求。max 模型耗时 1.621 / 2.096 秒，quick 为 0.783 / 0.952 秒。样本很少，提示词很短，没有工具调用，不代表真实群上下文、情感品质或端到端耗时；不能由此推断所有回复都能加速一半。详细记录见 `evidence/group-latency-model.json`；没有向评测发送实际私聊。

实际部署、数据库、服务与恢复点检查见 `evidence/group-latency-postflight.json`。若模型网络慢、调用工具或统一发送队列繁忙，仍可能超过上述模型样本时间。

## 回滚

生产使用原有补丁部署器的恢复点、启动验收与独立回滚看门狗。恢复该补丁前的插件源码和恢复检查点，再重启 AstrBot；不回滚真实聊天数据库。若快速别名不再使用，可在确认没有其他会话选择它后删除该唯一别名；也可保留为未被旧源码引用的兼容配置。整份配置备份只有在确认部署后没有其他配置修改时才可恢复，避免覆盖用户新设置。

初次上线验收曾在插件初始化时读取快速实例，早于框架加载模型，触发保守回滚；随后将实例健康检查移到框架启动完成钩子再验收。此失败没有被计为成功部署。回滚检查确认旧源码与检查点一致、旧配置恢复。
