# 原生概率与 P1 智能主动：独立开关

两条线路分别决定何时触发，共用同群的人格、Affect、记忆、图片来源约束和发送通路。原生指 AstrBot 的群消息概率回复，不是原生定时 Agent，也不新增另一套主动聊天插件。

## 主人命令

在已开启的 QQ 群中由主人发送：

| 命令 | 作用 |
|---|---|
| `/主动线路 状态` | 查看本群两条线路和 P1 子开关、面板概率及暂停状态 |
| `/主动线路 原生 开启` / `关闭` | 单独控制原生概率接话 |
| `/主动线路 P1 开启` / `关闭` | 单独控制 P1 智能主动 |
| `/主动线路 兴趣 开启` / `关闭` | 单独控制 P1 收到群消息后的兴趣插话 |
| `/主动线路 后台 开启` / `关闭` | 单独控制 P1 没有新消息时的后台主动联系 |
| `/主动线路 全部 关闭` | 关闭两条线路及子开关 |
| `/主动线路 全部 开启` | 开启两条线路及子开关，仍受总权限及限额约束 |

主人私聊使用相同命令，并在末尾添加群号，例如 `/主动线路 原生 开启 群号`；私聊查询用 `/主动线路 状态 群号`。非主人不能修改，群内只能管理当前群；网页聊天不能通过模型或终端代替 QQ 主人命令。

原有 `/群内主动 开启/关闭/状态` 保留为 P1 总开关，不修改独立的原生开关。兴趣和后台两个子开关都需要 P1 总开关开启；开启 P1 总开关不会擅自改动已保存的子开关。

## 四种组合

- 原生开、P1关：按 AstrBot 面板的启用状态、概率和白名单选群消息
- 原生关、P1开：依据兴趣与真实上下文选择插话，统一后台调度选择是否主动联系
- 两者开：P1 先选择有价值的兴趣插话，未选择时再按原生概率判定；同一条消息最多进入一次模型回复
- 两者关：不作这两类自主发言；正常 @、引用机器人的消息和已经承接的对话仍按正常路由处理

概率线路调用实际安装的 `GroupChatContext.need_active_reply`，保留原生概率与白名单语义。它不运行原生的独立发送处理器，否则会造成第二次模型请求和会话混用。两路均走本群独立上下文，不借用私聊人格、账号工具或历史。对明确 @ 其他人的消息继续保持克制。

## 共同约束

两路的开关独立，发送保护共用：群启用、QQ 目录有效性、自主等级、暂停、23:00–08:00 免打扰、冷却、每日额度及每次 2–5 秒延迟。原生 100% 表示满足这些条件的候选消息总能通过概率判定，不承诺每条群消息都回复。

主人在延迟期间关闭选中的线路，待发送消息会取消。关闭 P1 后原生线路仍能单独运行。P1 的后台子开关控制自动闲聊，不取消已明确安排的提醒；P1 总开关和自主空间暂停仍会约束其主动投递。

这里的开关不会自动控制另外创建的原生定时任务，也不会接管外部主动聊天插件。不要假定这些外部任务共享本项目的发送账本。

## 升级、持久化与回滚

各群独立保存，重启不丢失；新群默认原生关闭，P1 按原有默认值运行。已有群保留原来的 P1 开关，不因为原生面板开着或概率为 100% 就擅自启动概率线路。

控制数据存放于当前群 `scope.preferences.reply_routes_v1`，只允许主人命令写入，模型的可学习偏好接口拒绝这些键。写入使用事务，表达偏好更新不会覆盖操作者开关。无需增加数据库表或列。

兼容旧版本的单一 `interest_join` 位保存保守值：只有 P1 总开关和两个子开关都开才为 1。回滚到旧源码后，新原生线路不运行；部分子线路关闭的群会让旧 P1 主动整体保持关闭，避免回滚意外重启原本停用的活动。新版界面和模型状态使用完整线路状态，不把兼容位误当真实总开关。

部署前对 Agency 数据库及控制状态制作私有恢复点，并使用原有带启动验收和独立回滚看门狗的补丁部署。回滚只需恢复源码及检查点，不覆盖新增长的真实聊天记录。

## 验证与边界

335 项完整离线测试、168 项中性核心测试；原生 SDK 验证命令解析、主人权限、群隔离、四种组合、原生面板启用/概率/白名单、独立子开关、同消息去重、共享发送回执、群目录过期保护、延迟关闭取消和两路关闭后的正常 @ 回复。原有群聊、QQ 主动开话题、图片及现有/新范围隔离回归检查继续通过。

测试使用合成会话和假 QQ 传输，没有向真实群发送测试消息，没有新增模型评测 API 请求，也没有把测试数据写入生产记忆。实际部署结果见 `evidence/reply-routes-postflight.json`；原生专项见 `evidence/reply-routes-native.json`。这些检查不能保证所有未来 AstrBot 版本兼容。
