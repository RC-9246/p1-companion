# 模型提出修复，独立程序验收

P1 Companion 的常规维护先处理已知故障：恢复封存源码、修正受支持配置、重启或重建已知容器、验证数据库快照。模型不可用时，这条恢复链仍可运行。它不是任意新缺陷的自动修复器。

可选的候选补丁监督器再开放一小块新代码修复：三个 QQ 纯格式函数 `casual_tail`、`qq_reply`、`split_reply`。模型可以读取函数、提出替换稿；只有 root 监督器可以运行测试和发布。其他模块的新逻辑缺陷仍通过受审查的工程发行版修复。

## 实际流程

1. 管理员先封存已经验收的安装版本。候选基线必须和封存版本、当前文件同时匹配。
2. 主人范围可通过 `p1_agency` 的 `repair_source` 读取单个函数，通过 `repair_propose` 提交固定结构的提案。群友不能取得此入口。
3. 监督器检查目标、函数签名和 AST。拒绝导入、文件/网络调用、私有属性、修改测试、权限和策略，以及夹带无关内容。
4. 同一套只读可信测试分别运行旧代码和候选代码。旧版必须确实失败，候选必须通过固定用例和生成属性检查；“没有复现问题”不能发布。
5. 执行环境无网络、只读根目录、无额外能力，使用已固定的本地镜像，限制内存、CPU、进程数与执行时间。
6. 管理员明确启用自动纯函数修复后，合格候选才替换该文件并重启 AstrBot。正常观察 15 分钟后才更新封存源；异常、进程中断或发布失败走代码回滚。当前聊天数据库不回退。

提案不等于修复成功，单元测试通过不等于线上效果已证实。状态分为待验收、隔离通过、观察中、已接受、已回滚、拒绝等阶段。root 账本在执行前保留尝试记录，滚动一天最多两次新尝试，冷却 30 分钟，不能靠清空聊天绕过。

## 安装和关闭

先按 [恢复指南](recovery.md) 完成主维护链与真实服务验收，再由已获授权的管理员从完整项目目录执行：

```sh
# 只查看，不修改
python3 scripts/install_repair_candidates.py --root /srv/p1-agent

# 安装并仅允许隔离验收
sudo python3 scripts/install_repair_candidates.py --root /srv/p1-agent --apply

# 明确允许上述三个纯格式函数在通过监督器后自动灰度
sudo python3 scripts/install_repair_candidates.py --root /srv/p1-agent --apply --auto-pure
```

首次安装程序拒绝覆盖已有监督器。更新监督器必须走工程备份、测试、代码升级及重新封存流程；不会删除旧尝试账本以便重新执行。安装失败会停止新定时器、移出本次新源码并保留私人恢复记录。

`/自修复 关闭`、项目暂停和停用维护模块均阻止新的候选执行。普通聊天模型不能开启 root 自动发布选项。主人可用 `p1_agency` 的 `repair_status` 查看闭合状态摘要，不读取 root 路径或原始日志。

## 复现隔离验收

`tests/isolated_candidate_acceptance.py` 必须显式传入 `--run`、新的实验目录、私有凭据文件和不可变镜像 ID，由 Linux 管理员运行。它只挂载生成的缺陷代码及实验状态，实际调用现有 DeepSeek 提出补丁，随后执行无网络测试、真实 15 分钟观察和真实服务停止后的回滚。不会挂载正式聊天数据库或发送 QQ。

这仍是有限的恢复能力：root、内核、磁盘、网络、systemd、账号验证同时失效，或未知缺陷超出允许函数时，需要外部维护。固定用例和随机属性不能证明程序没有任何缺陷，也不能保证十年免维护。请保留离机备份与人工恢复手段。
