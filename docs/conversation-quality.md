# 让表达留给对话，把控制留给程序

这轮围绕三个实际问题改进：表达偏好被当成要求独处；问起伙伴自己的关注时，检索依赖字面关键词而漏掉已有来源；短回复审校倾向整段重写，容易磨平原本的观点和情绪。它们不靠再叠加一个主动聊天插件解决。

## 本轮机制

| 改动 | 实际行为与边界 |
| --- | --- |
| 区分当前交流目的 | 分享、让伙伴自己选、询问其关注、调整表达、暂停主动联系和结束本轮分别处理。模型给出的目的标签需要当前原文证据；程序可以校正明确的表达偏好误判，但不据此授予权限 |
| 暂停联系与当前回复分开 | 明确暂停仍写入原有调度控制；对方主动回来聊天时可以继续回应。真正结束本轮仍允许收住，不把暂别当关系扣分 |
| 找回自己的关注 | 自选话题时可检索当前范围里由真实工具回执或已送达立场支持的记录，不拿用户的困难冒充自己的活动。保留日期、来源和摘要/全文/视频采样等覆盖范围 |
| 减少无关上下文 | 社交轮次只投影当前目标、近期记录和明确偏好；完整控制、用量和工具检查仍在程序里。需要附件或操作资料时保留完整路径。21维状态继续保存；不再把没有具体来源的情绪类别当成往事提示 |
| 审校只做局部修改 | 短社交回复只接受最多三处可定位替换；拒绝大范围改写、新数字、URL、结构化输出和未知字段。保留有依据的反应、幽默与分歧；失败保留原回复 |
| 让审校看到必要证据 | 除当前话语外，带上有界的同范围前情、持续事项与群内发言人绑定。清空或撤权发生在调用前后时，丢弃过期结果 |
| 缩小配图候选 | 私聊和群聊从完整审核图库选最多八个候选；按语境与近期尝试排序，完整图库仍可搜索。发送前继续验证素材、冷却、范围与真实回执 |
| 阻止虚构事项入库 | 引用、假设、剧本、翻译或明显注入中的事项，不因分类器提取了一句原文就成为当前人的持续经历 |

这些是应用层状态、检索和表达的改动，不训练模型权重，不证明主观情感，也不能保证每一条回答符合某个角色。公开版本继续使用中性人格与空图库，私人角色设定和原作图片不随代码发布。

## 借鉴与取舍

SillyTavern 的[角色设计文档](https://docs.sillytavern.app/usage/core-concepts/characterdesign/)说明角色定义会持续占用上下文，示例对话也会影响语气。本项目据此优先减少重复说明，保持角色核心和当前交流重点，而不是无限增加人格段落。这是设计取舍，效果由自己的实测判断。

Generative Agents 的[原始检索实现](https://github.com/joonspk-research/generative_agents/blob/main/reverie/backend_server/persona/cognitive_modules/retrieve.py)区分记忆类别，并综合相关性、时间和重要程度。本项目延续本地轻量排序，增加“谁的经历、凭什么知道”的过滤；没有接入其外部嵌入服务，也没有把模拟世界中的事件当作真实活动。

DeepSeek 的[思考模式文档](https://api-docs.deepseek.com/guides/thinking_mode/)区分思考强度和工具协议。本项目保留复杂语境的 max、普通回复的原有档位与输出长度分离；快速分类和局部审校不使用深思考。评测中的工具续问保留协议所需字段，但不把隐藏推理写入对话报告或展示给用户。

## 怎样评估

旧的纯对话脚本只覆盖一部分管线。新的[原生流程评测](evaluation-native.md)使用实际 AstrBot 请求/回复钩子、群路由和隔离记忆工具，分别记录生成稿、最终文本、调用、输入用量、时延、旁听和失败。工具闭环只覆盖会话记忆与已有知识查询，不能冒充浏览器、账户操作或实号 QQ 验收。

开发样本用于找问题；首轮48组双轮比较之后，这48组用于回归，第二轮另冻结16组新情境。模型评审交换展示顺序，保留平局与分歧；同模型评分不能替代独立人工观察，亦不能把一次较好的措辞宣称为达到设备或模型极限。最终结果与部署证据见[本轮验收记录](verification-results-0.22.md)。
