# v0.21 设计目标与验收边界

本轮把原设计逐项对应到实际入口、回执和故障测试。结论必须分开看：工程路径可用、合成对话有改善、真实长期相处达标，是三种不同的证据。不能把测试次数、情绪维度、max 次数或插件数量当作“已经像人”的证明。

## 原来的二十个方向

| 方向 | v0.21 的具体实现 | 验收入口与边界 |
|---|---|---|
| 自主目标 | 持久目标、优先级、步骤、时限与额度；后台可提出暂缓、恢复、放弃及重排 | `test_goal_planner.py`；人工暂停、提醒和临时附件任务受独立保护，计划不能宣称已经完成 |
| 长期兴趣 | 讨论、真实公开阅读与视频片段形成独立来源；缓慢更新兴趣；资料可整理为清单 | `test_audit_workflows.py`、`test_experience.py`；八类种子不是模型知识边界，没有开放无约束的分类或权重训练 |
| 情绪调节 | 强度与分类置信度分开，保留混合感受、惯性、缓解和解决状态 | `test_experience.py`、实际模型多轮评测；有界角色状态，不诊断用户心理，不惩罚不回复 |
| 人格细节 | 稳定核心、Concern、可修正 Stance、可学习表达分层；允许不赞同和自然收住 | `integration_audit_contracts.py`；立场需真实已送达语句或真实资料依据，角色相似度仍需人工长期评价 |
| 共同经历 | 用户原话、实际回复回执、公开资料和活动覆盖形成可追溯 Episode | `test_experience.py`；自己的话不成为用户事实，计划、标题和图片标签不冒充体验 |
| 记忆检索 | 全范围候选评分、来源/时间加权、去重、冲突提示；移除先截取300条的盲区 | `test_audit_scopes.py`；本地轻量检索，不是外部向量服务，也不是无限模型窗口 |
| 自我学习 | 明确纠错快速生效，区分今天/暂时/长期，取0–2条相关表达原则，可解释和回滚 | `test_learning_continuity.py`、`integration_learning.py`；固定许可词表，不修改模型权重、核心、白名单或测试 |
| 群内理解 | 群与成员隔离、说话人/引用绑定、真实近期节奏、连续摘要游标、过时草稿撤销 | `integration_scope_matrix.py`、`integration_group_control.py`；拥挤真实群的长期误插话率仍需观测 |
| 主动交流 | 一个调度时钟；原生概率与P1分别控制，兴趣和后台再分开；真实回执去重 | `integration_reply_routes.py`；每群实时逻辑回复上限999，后台另起话题仍用独立4/16额度，不要求用满 |
| 后台公开研究 | 依据兴趣/目标/关注选择资料，记录摘要或读页覆盖；额度耗尽改活动，连续失败退避 | `test_audit_workflows.py`；公开共享缓存不能装私聊资料，网页不能改权限 |
| 提醒与待办 | 明确意图、上海时区、持久化、改期/取消、送达确认、发送未知不重试 | `integration_agency_failure.py`；免打扰和发送保护可推迟提醒，不能承诺秒级到达 |
| QQ细节 | 原生序列化、非零消息回执、分段延迟、原生表态/撤回/文件接口和受控记录转发 | `test_qq_actions.py`、真实SDK；表态、撤回、上传等仍以实际 SnowLuma 回执为准，模拟回执不是实号送达证明 |
| 表情理解 | 审核标签、按范围重复抑制、偏好与关闭在途生效、可添加私人素材包 | `test_reactions.py`、`test_audit_installation.py`；公开库为空，测试生成像素，不分发角色原画或私人图库 |
| 跨会话媒体 | 来源与操作对象绑定，OCR/解析、秘密标记、接收范围检查、发送前再核对 | `test_qq_actions.py`；不能可靠检查的附件继续拒绝，不保证任意图片隐写或所有秘密都可识别 |
| B站私人整理 | 私密收藏/稍后再看、真实播放进度和断点、片段观察、兴趣与笔记 | `test_leisure_policy.py`、`integration_leisure.py`；有进度不代表理解全部视频，没有音频理解，不开放评论/弹幕等公开动作 |
| 资料产出 | 受配额保护的文本、表格、网页、代码实验产物；来源边和可继续读取的分段结果 | `test_goal_planner.py`、工作台测试；附件派生内容继续受同一保留期限约束，不借资料产出永久保存 |
| 自主管理 | 可选活动、任务次序、休息、低风险表达/节奏参数及有界日时长 | `test_agency.py`；任务数据不能改变实际权限，模型不能解除人工暂停或修改密钥 |
| 维护能力 | 已知源码/配置/容器/数据库恢复，独立看门狗；额外受控纯函数候选修复 | `isolated_repair_acceptance.py`、`repair_chain_acceptance.py`、`isolated_candidate_acceptance.py`；新任意缺陷、硬件和账号验证不保证自动处理 |
| 成本与性能 | 前后台门控分开，后台至多40/Agency总200；公开读取240；跳过过时机会，记录实际SDK用量 | `integration_latency.py`、`test_thinking.py`；普通前台模型另计，选择/准备不等于成功完成，max也可短答 |
| 可见控制 | `/群主动诊断`、`/主动线路`、`/自主空间`、`/思考状态`、`/学习`、`/自修复` | `integration_audit_contracts.py`；输出当前获准范围的摘要，不公开内部推理或其他人的私聊 |

## 五轮验证怎样计算

五轮必须针对同一可执行源码版本，用新的临时状态分别运行。正式记录列出每轮源码签名、退出状态、用例数、跳过项、耗时及对应证据层级。修正失败后另开新记录，原失败记录保留；不能把之前不同版本的五份“通过”拼在一起。

- 离线：完整单元/回归集、源完整性和真实 Node.js 向导状态检查。
- 真实框架：安装中的 AstrBot 镜像，临时数据，真实插件和消息组件，模拟 QQ/浏览器传输。覆盖新旧白名单、新旧群、清空、撤权、学习、图片来源及独立开关。
- 真实服务：无网络实验容器、真实服务停止/重建、真实 systemd 和中断恢复；不操作正式会话。
- 真实模型：仅合成场景和已有获准 DeepSeek。开发集、留出集、审查分歧、失败以及实际用量分别记录。
- 部署观察：源码/配置差异、恢复点、健康与数据库完整性另记，不能由上面的测试自动推出。

复现本地五轮回归：

```sh
python3 -m pip install -r tests/requirements.txt
python3 scripts/verify_five_rounds.py --output /private/path/verification-run --node /absolute/path/to/node
```

命令不会 SSH、调用模型、发送 QQ 或改生产。Linux root 相关用例在普通用户环境会明确跳过；Windows 启动器和真实服务需各自环境，不能靠本地跳过当作通过。

## 情感效果与没有完成的证明

评测工具在 `evaluation/`：A为旧策略，B为来源/表达修复，C增加持续关注，D再加入表达学习。开发20场景用于诊断；另有60个原创独立多轮场景。评审交换展示顺序，按场景聚类汇总，保留平局与分歧。它是模型评审，不是独立人工盲测；使用私人角色配置的原始输出保留在私人证据里，公开包只提供通用机制、合成用例与汇总。

功能性回归通过不保证对话质量提升。少量样例更自然，也不代表角色忠实度或情感体验达到理论上限。主观效果没有统计支持时如实标明，没有以增加插件数量替代效果验证。

尚不能证明的目标包括：十年免维护、全模块任意新缺陷自动修复、无限上下文窗口、模型权重自训练、所有资料完整理解、全部QQ动作实号兼容，以及 Windows 从空系统到重启/扫码的完整硬件验收。它们不是这轮测试可以消除的边界。

## 升级和回滚

先备份并保存当前文件所有权、权限、镜像与在线SQLite快照，在隔离副本完成迁移验收。部署只改审查过的源文件和明确策略，保留私人角色、账号、图库及当前聊天数据；恢复链的封存副本一起更新，避免看门狗恢复旧代码。

回滚恢复旧程序和明确改过的配置，保留新聊天数据库。新增表采用可兼容方式，不能为了退版本把旧快照压回新历史。数据库本身损坏时才考虑经完整性验证的快照，恢复后停住未知主动动作，重放清空水位并降低旧资料可信度。

详见 [恢复流程](recovery.md)、[候选补丁监督器](repair-candidates.md) 和 [安装/升级约束](core-upgrades.md)。

最终结果见[五轮验收报告](verification-results-20261029.md)与[42项修复对照](repair-ledger-20261029.md)。当前策略60组对话复测未显示统计显著的自然度优势；工程验收不关闭这项主观质量目标。
