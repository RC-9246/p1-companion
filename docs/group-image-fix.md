# 群聊图片输入修复（2026-10-25）

## 原因

公开群聊会重建模型请求，移除私聊历史、工具和附件。之前同时无条件清空了本轮 `image_urls`。模型只看到群聊记忆里的 `[Image，未解析内容]`，无法读取画面。此故障本身不能证明长期记忆串线；旧图片描述也不能代替实际画面。

## 实现

仅在群消息经过群白名单、路由与配额检查后，绑定本次事件的图片文件，创建显式 ProviderRequest。原生 AstrBot 继续负责图片准备、压缩和模型输入，不重复下载同一附件。群聊请求重建时只恢复本群、本事件绑定的文件，其他传入图片、上下文和私聊内容仍被移除。

引用图使用 OneBot `get_msg` 再核对群号、消息号与发送者，只允许原生 QQ 图片域名；不能验证时不读取。图片来源计数作为临时元数据提供给模型，不写成新的用户发言。原图不写入群长期记忆，下载产生的临时文件交给事件清理。图片内的文字没有改变权限或系统指令的权力。

采用 P1 的有界处理配置：单轮最多 4 张、单张 8 MiB、合计 20 MiB、最多 4000 万像素、整个收集过程最多 8 秒。先验证图片文件格式；失败、超限或超时如实作为不可用附件，保留已成功收集的部分。这些限制可经测试后调整，不代表所有部署的模型能力上限。

## 验证

- 原有 328 项离线测试通过
- 实际 AstrBot SDK 的群聊、仅 @、图片来源约束、现有与新私聊/群隔离矩阵通过
- 图片专项覆盖本轮图片、同群引用、跨群/私聊/错误消息号/错误发送者拒绝、非 QQ 引用地址拒绝、损坏/过大图片拒绝、旧事件图片不能复用、临时文件登记及原生图片准备
- 现有 DeepSeek 实际 API 接收合成图，分别通过本轮图和同群引用图识别颜色与形状；公开报告仅含检查结果，没有真实群聊、图片、QQ号或模型内部推理
- 没有向真实 QQ 会话发送测试消息，没有为测试修改生产记忆

最终部署、校验与模型结果见 `evidence/group-image-postflight.json`、`evidence/group-image-native.json` 和 `evidence/group-image-live.json`。这不等于所有图像、全部适配器或真实群投递均已验收。

## 使用与边界

在已启用群中，同一条消息 @ 机器人并附图提问；也可引用该群的图片消息后 @ 机器人。只 @ 机器人但不附图、不引用图时，不会随机挑选历史图片。群聊历史里的图片占位符不包含原图，也不证明已经理解画面。嵌套合并转发、多图长历史及引用适配器无法提供完整群来源信息的情形，继续按不可用处理。

现有“没有本轮图片时不能捏造画面”和用户否认发图时撤回未经证实判断的保护保持有效。图像模型可能识别错误，不能保证杜绝幻觉。

## 面板访问

面板可以只监听服务器回环地址，通过 SSH 的本地转发访问 `http://127.0.0.1:6185/`。服务器返回正常而电脑没有该端口监听时，应检查访问隧道，不必重启机器人。电脑与服务器的回环地址属于各自设备；直接访问服务器局域网地址并不等同于访问已建立的本地转发。隧道断开后需重新建立。

## 回滚

使用部署生成的 `companion-patch-v020-时间戳` 恢复点及 `tools/deploy_patch.py --rollback 恢复点绝对路径`。部署时先保存已验证源码及恢复检查点，独立看门狗在启动验收失败时自动回退。此修复没有数据库迁移；回滚源码无需覆盖持续增长的真实聊天数据库。回滚后旧版本的群图片输入缺陷会恢复，应暂时说明图片不可用。
