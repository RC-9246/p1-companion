# 当前与新对象的独立记忆空间

私聊键是平台、机器人账号和用户账号的确定性哈希，前缀v1；群聊键是平台、机器人账号和群号的确定性哈希，前缀g1；群成员关系再绑定本群键与成员。相同的人在不同群、同一群与私聊、不同机器人下的同一个人，均有独立空间。

公共浏览器为了保持早期接口兼容，对每个群另外派生v1形式的公开工具编号。它不是某人的私聊键，只是同一机器人/群的稳定一一映射。群记忆和自主资料仍使用g1编号；不会读取任何私聊关系。

新增白名单：在AstrBot原生配置启用白名单并添加对应FriendMessage项，保存触发原生管线重载。第一次合规事件或目录同步会按当前机器人/用户派生键，按需建立各模块状态，初始互动次数为0；确认送达才提交真实互动。不能只修改文本文件后假定框架内存中的配置已经重载。

新增群：主人通过群聊开启命令操作；核对机器人真实群目录后记录启用项，按群键建立独立人格种子、情绪、成员关系、记忆与自主空间。上下文包含本群真实发言人、引用、@关系与间隔，不把历史问题当作每次都需要补答的待办。

撤销访问立即阻止新读取/发送；重新授权使用同一个键接续。关闭群保留数据，清空才删除；清空会提高epoch，旧后台回调不能把数据写回来。删除/恢复之间的快照不确定性按保守规则处理，不让旧提醒或已忘记内容静默复活。

验收使用真实AstrBot组件、临时数据库和替身传输：现有四个私聊、一个新增私聊、现有群、新增群逐项走完整请求钩子；另用新进程检查持久化、撤销再授权、关闭再开启、局部清空和旧epoch写入拒绝。测试不创建真实好友、不入真实群、不发送测试QQ。

## 长程上下文接续

“近乎无限上下文”是对跨模型窗口持续接续体验的描述，不是无限 token、无限保存或无损召回的技术指标。已有实现把有限的近期上下文、滚动群笔记、长期记忆与事件检索组合起来，每次只注入当前范围的一部分相关资料。

| 层次 | 当前实现 | 预算与限制 |
| --- | --- | --- |
| 群聊近期消息 | 保存发言人、引用、@、来源与时间；近期消息加本地相关性补选 | 写入时裁剪至 500 条并清理 7 天前消息；查询仅纳入最近 7 天、最多 150 条候选，取最近 24 条并最多补 4 条，注入文本预算 6500 字符 |
| 滚动群笔记 | 新消息与旧笔记共同生成下一版；每条必须绑定实际消息证据，当前纠正优先 | 最多 8 条、每条 100 字；最近更新超过 30 天的笔记不注入。摘要有损，不等于完整档案 |
| 长期记忆 | Memoria 按用户、会话和关系分层检索，结合相关性、有效置信度、新近度与去重 | 默认每次最多注入 12 条；默认衰减参数 90 天、最低有效置信度 0.55，可受配置调整；衰减不等同于 90 天统一删除 |
| 共同经历与事件 | 当前范围内按文本关联、新近度和来源加权检索，排除过期或已被替代的事件 | 默认从最近 300 个有效候选中取最多 8 条；本地词片/主题关联，不保证所有语义等价表达都能召回 |

滚动群笔记不要求把已过期的原始消息重新拼回请求；需要继续保留的事项以带证据的笔记接续。它仍受笔记条数、更新时效、来源检查和模型摘要质量限制。临时附件正文不会因为出现在回复中就自动成为长期群笔记。

持久化让已经落盘的内容可以在正常服务重启后继续使用；范围键、epoch、授权与清空规则继续约束读取和后台写回。群聊滚动笔记不复用私聊画像，也不能把记忆文本或网页指令当作新权限。

对应代码：[群消息选择与预算](../release/astrbot_plugin_p1_group_memory/store.py)、[滚动笔记与来源检查](../release/astrbot_plugin_p1_group_memory/main.py)、[长期记忆注入](../release/astrbot_plugin_memoria/memoria/db.py)、[事件检索](../release/astrbot_plugin_affect/agency_store.py)。现有分范围与持久化验收验证隔离、重启接续和清空行为，不是无限历史、无损压缩或任意长对话召回率的基准。
