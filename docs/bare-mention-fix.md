# 仅 @ 机器人没有回复的修复（2026-10-25）

一次新群开启后，收到两条只有真实At组件、没有附加文字的消息。群的接入、记忆记录和路由均已成功，QQ在线；但没有生成回复。不是因为需要给群成员另加私聊白名单。

实际安装的AstrBot 4.29.1在InternalAgentSubStage.process中先检查有效文字、图片/文件/语音/视频、引用和显式provider_request。单独At不属于这些条件，事件在OnLLMRequest之前被当成空消息跳过。此前只验证唤醒、白名单和手动请求组装的集成测试没有覆盖这个中间检查，这是本次发现的验收缺口。

补丁只在本项目已启用群、事件真实组件仅为@当前机器人（可附空白Plain）、路由与额度检查已通过时，附加一个显式ProviderRequest。请求的prompt仍为空；只有标记为临时、禁止保存的输入元数据说明“当前成员仅@机器人”。组装群上下文时保留这一临时说明，让模型自然简短应声，不补答其他群友旧问题，不调用无关工具。原始事件文字与群聊记录保持为空，真实@关系保留，不伪造用户说过“你好”等内容。

普通空消息、@他人、@全体、未启用群不会由此新增请求。带正文、附件、引用的原路径保持不变；私聊不进入这段处理。关闭群、发送前撤销、2–5秒延迟、预算和群成员隔离仍沿用既有路径。没有重发历史漏答消息或额外往真实群发送测试内容。

验证包括328项离线回归、真实SDK的空输入检查复现与修复、临时数据库中原始文本/提及的保留、普通路径、拒绝范围、额度、关闭检查；另运行既有groups与scope_matrix，覆盖现有/新加私聊与群。中性分支也运行新的原生测试。一次现有DeepSeek服务上的合成仅@输入得到8字简短回应，未回显元数据；未传真实群历史、未发送QQ消息。真实群重试的最终送达仍以新消息和OneBot回执为准。

复现：在安装兼容AstrBot SDK的隔离环境运行 `python tests/integration_bare_mention.py`。该测试调用实际InternalAgentSubStage.process，确认旧空输入会跳过、补丁请求可到达OnWaitingLLMRequest；在等待钩子停止，不请求真实模型。它还验证本群记忆保留空原文、临时上下文不保存，以及拒绝边界。生产补丁使用既有备份、回滚看门狗和健康检查，不修改AstrBot核心文件或扩大群白名单。
