# 按需要组合功能模块

[← 项目首页](../README.md) · [组件升级](core-upgrades.md) · [模块清单](../modules/catalog.json)

打开向导的 **08 · 模块组合**，先“读取已安装状态”，选择模板或勾选功能，预览变更，再应用。运行时不必卸载整个项目来关闭浏览器、B站、工作流或后台活动。

模块开关与原来的会话授权叠加：启用一个模块不会新增主人、好友白名单、群、域名、账号权限或外发授权。普通 QQ 回复、2–5 秒发送节奏、分范围记忆和群私隔离保留在必需核心中。

## 第一版包含 15 个单元

| 模块 | 作用 | 可选性 |
| --- | --- | --- |
| 陪伴核心 | 情绪/人格基础、独立记忆、群私隔离、权限和 QQ 规范 | 必需，不能通过模块管理移除 |
| 表达与经验学习 | 自动提取与使用表达偏好、经验卡 | 可停用；旧卡片保留，仍可按原权限查看/撤回 |
| 交流复盘 | 从已送达互动中整理表达经验 | 依赖学习模块 |
| 表情包表达 | 审核图库、选择、发送与重复抑制 | 可停用；素材不删 |
| QQ 扩展动作 | 表态、本人撤回、获准转发、资料分享 | 可停用；普通聊天仍保留 |
| 后台目标与活动 | 后台目标、研究/整理选择和到期提醒 | 可停用；任务队列不删，过期提醒沿用原过期规则 |
| Companion 主动交流 | 兴趣插话和主动联系 | 依赖后台活动；与 AstrBot 原生主动回复开关独立 |
| 公开搜索与浏览 | 搜索、隔离浏览器及域名代理 | 可停用或移除其两个服务容器 |
| B站私人活动 | 独立浏览器、私人整理 | 可停用或移除其两个容器；登录与账号数据保留 |
| 文件与实验工作台 | 解析、OCR、格式处理和隔离实验 | 可停用或移除工作台容器 |
| 公开工作流 | 已批准的 n8n 公开资料工作流 | 依赖公开网络模块；可移除容器，不删数据库 |
| 运行时 MCP 工具桥 | 按已启用模块提供运行时工具 | 可停用；工程只读 MCP 接口独立保留 |
| 已知故障自动维护 | 巡检和修复链定时器 | 已通过向导准备后可启停 |
| 内存压力保护 | 资源守护定时器 | 已准备后可启停；停用不撤销既有内核限额 |
| 只读资源面板 | 资源采集与本机面板 | 已准备后可启停 |

这是**功能开关、可选服务生命周期和依赖管理**的模块化。当前八个基础插件存在共享接口，仍随基础包准备；不是把所有 Python 文件变成任意可卸载的独立包。关闭学习等功能会停止对应的自动调用/注入，而不会破坏核心所依赖的初始化接口或删除历史数据。

## 四种组合模板

- **轻量聊天**：核心、学习、复盘、表情和 QQ 扩展动作
- **日常陪伴**：聊天模块加后台活动与 Companion 主动交流
- **资料与工具**：核心、学习、表情、QQ 动作、公开网络、工作台、工作流和 MCP
- **全部功能**：全部已准备的可选功能；宿主保护保持原来的选择

模板用于运行组合，不宣称只下载所选模块的所有依赖。当前新安装仍先准备完整基础包及镜像，验收完成后按需减少常驻服务；资源收益取决于原来实际运行的组件。没有以合成测试镜像的内存代替真实 P1 节省量。

## 启用、停用、移除的区别

| 操作 | 实际结果 |
| --- | --- |
| 启用 | 自动补齐清单依赖；启用功能入口，按已保存配置启动或重建本机已有可选服务 |
| 停用 | 隐藏并拒绝对应模型工具，停止新后台活动或学习；服务模块停止容器并将重启策略设为 no，避免宿主重启后自行复活 |
| 从运行组合移除 | 在停用基础上移除已登记的可选服务容器，Docker 使用 `v=false`；镜像、bind 数据、命名卷、登录与数据库保留 |
| 重新启用 | 使用保存的本机镜像、挂载、网络、限制和数据重建；不生成新账号，不清空记忆，不任意拉取第三方镜像 |

“移除”不会删除共享基础插件或运行数据。未安装的宿主工具、已被管理员清理的镜像，或尚未登记的外部组件会返回 `module_requires_setup`，需先通过部署/安装流程准备。它不是任意仓库插件的自动下载执行器。

模型工具的开关在实际执行入口再次检查，不只隐藏按钮：原生工具、运行时 MCP、后台规划、主动发送及学习/复盘均接入；已发出的消息和已开始的外部动作不能承诺撤回。资料整理仍可能保留核心支持的简单笔记产出，关闭工作台主要关闭解析/OCR/格式处理与隔离实验服务。

## 为什么停用后不会被巡检重启

管理员的目标组合保存在宿主机 root 私有目录；维护程序读取只包含明确服务名的停用意图，跳过这些服务的重启和重建。它将“有意停用”单独报告，不能当作健康运行，也不计入启用服务的正常数量。

运行时另有无账号信息的功能镜像文件，供插件快速读取和缓存；它只是功能配置，不能授予新权限。维护动作的源记录位于运行容器之外，聊天任务数据不能改写它。损坏的宿主意图文件不会被删除或默认为允许重启全部服务；核心仍保留，需管理员处理可选模块策略。

调整先保存旧组合、服务/重启策略和宿主单元状态，再记录意图。中途失败尝试恢复此前组合；独立 systemd 入口处理进程中断，自动恢复次数有上限。回滚不覆盖聊天数据库，外来镜像或挂载变化会阻止自动接管。

## 兼容与首次使用

使用最新完整包打开：

```sh
sudo python3 deploy/wizard.py --manage-root /srv/p1-agent
```

新设备先完成第六步的人工试聊验收和安装收尾，再重新打开向导使用模块组合，避免在安装验收中途停用它正在检查的服务。旧部署必须先更新运行时模块协议及维护程序；健康记录的 `module_policy_schema=1` 和维护代码标记均通过后才允许调整，不给旧程序提供无效开关。

组件升级观察期间不能调整模块。反过来，模块变更未完成时也会阻止新的核心升级。非标准容器名、外来 Compose、挂载或镜像变化不会被静默接管。

## CLI 与供 AI 阅读的清单

```sh
# 纯本地读取声明；不启停服务
python3 services/modules/manager.py catalog

sudo python3 services/modules/manager.py --root /srv/p1-agent status

# 模板保留已开启的宿主保护；只显示计划
sudo python3 services/modules/manager.py --root /srv/p1-agent plan --profile chat

# 实际应用
sudo python3 services/modules/manager.py --root /srv/p1-agent apply --profile chat

# 关闭公开网络，并自动关闭依赖它的工作流
sudo python3 services/modules/manager.py --root /srv/p1-agent apply --disable public_web

# 从运行组合移除未选的可选服务容器，数据保留
sudo python3 services/modules/manager.py --root /srv/p1-agent remove --profile chat

# 人工处理阻塞原因后，显式重试最近一次组合回滚
sudo python3 services/modules/manager.py --root /srv/p1-agent rollback
```

工程 AI 可先读 `modules/catalog.json`、运行 `catalog` 或使用现有只读工程接口读取项目说明，再提出模块组合。应用仍属于管理员已授权的宿主操作，不能靠编辑任务 JSON 绕过权限。

## 增加一个模块

1. 在版本化清单增加稳定 ID、名称、类型、依赖和说明；依赖必须无环。
2. 添加经过审阅的固定适配器。功能模块接入实际运行入口；服务模块明确容器和镜像/挂载约束；宿主模块明确单元。没有适配器的声明会被拒绝。
3. 新功能同时接入工具可见性和执行检查；不把来源、任务或网页内容当作新授权。
4. 增加依赖、数据保留、故障/中断与恢复测试；更新文档和明确的新源文件清单。
5. 在隔离环境验收后发布，再通过受控方式更新现有运行时与恢复检查点。
