# 群内主动命令入口修复（2026-10-24）

用户提供的失败记录来自AstrBot网页ChatUI，读取代码工具实际返回exit code 0；该轮18:27请求与机器人重启时间重合，流式连接中断，刷新后会话列表恢复。网页身份不属于QQ主人，原处理器又在停止事件之前返回，命令便可能进入模型与工具回合，没有实际执行开关。现在这类命令先停止事件，网页直接说明应在QQ主人入口使用，不通过终端或模型代替授权。

另外发现，原先主人管理命令仅允许私聊，群入口又统一移除了插件命令处理器。因此在群内输入“群内主动”无法执行开关；之前的测试只验证数据库开关影响聊天行为，没有覆盖群内命令入口。

现在同一配置主人可以在已启用群内直接使用：

- `/群内主动 开启`
- `/群内主动 关闭`
- `/群内主动 状态`（省略“状态”也可以查询）

主人私聊继续支持 `/群内主动 开启 群号`，也接受 `/群内主动 群号 开启`。只有一个已启用群时，私聊可省略群号；多个群必须明确指定，不能默认修改全部群。

群内入口仅允许操作本群。普通成员、未启用群、引用或转述命令都不能修改开关；其他插件的管理处理器不会被放行。不调用模型判断管理权限，不接触私聊人格或群聊记忆。模块未就绪会给出明确提示。回复仍等待2–5秒，并在发送前重新检查主人权限和群授权。

开关控制兴趣插话和自主发起话题，被点名的正常回复继续有效。开启表示允许选择发言，仍受自主等级、暂停状态、免打扰、冷却、无人回复暂停与配额约束，不保证立即发言。

新增 `tests/integration_group_control.py` 使用 P1 实装 AstrBot 的命令过滤器和唤醒阶段，临时数据库与替身QQ传输验证两种参数顺序、开关持久化、查询、后续新群、越权阻止、跨群隔离、准备状态以及等待期间撤权取消。生产仅修改主插件的 main.py 和 group_runtime.py；发布保留恢复点。

本次验收结果见 `evidence/group-control-postflight.json`。原299×5轮完整验收属于修复前版本；修复后另做5轮命令专项、299项回归及agency/groups/scope_matrix集成检查，不能把两组测试混写成修复后五轮完整验收。测试不向真实QQ发送消息，也不调用模型。

实际Safari网页验证：刷新恢复会话列表后，提交 `/群内主动 状态`，立即显示QQ主人入口提示，无新的工具调用卡片、无Load Failed。原群的开关经只读核对已经开启，等级3、未暂停；本次没有为了演示向真实QQ群发送消息。网页截图、会话标识和实际群号不进入分发包。
